# 7.11 Stateful collaborators are built by the composition root and passed in

Rule: [§7.11 in the code standards](../code-standards.md#7-design-solid-cohesion-and-decomposition);
the root, the orchestrators and the existing cases are in
[B2](../code-standards.md#b2-module-taxonomy-the-on-disk-decomposition).

## Why

A collaborator that holds state and serves more than the script that builds it (a tracker, a
debugger hook, a monitor, a transport) has one correct instance. When the composition root builds
it, one file shows the whole object graph and the order it starts and stops in. When a user builds
or defaults its own copy, there are two instances of the same state, nothing keeps them in step,
and they disagree without an error.

The collaborator reaches its users in one of three ways:

- an `_init` argument;
- a `register(...)` parameter;
- a `set_*`/`clear_*` pair on the user's instance that the root calls at start-up and undoes in
  teardown (8.5). A static setter that fills a `static var` is a global holder instead (7.13).

The one orchestrator that alone uses a child may build it (7.2): that child serves nobody else.
A user with nothing injected reports that state (an empty result, a note, a `false`) instead of
inventing a substitute.

## Good

The composer builds the debug-session tracker once, hands the same instance to the debugger
bridge that feeds it, and passes both to the command registrars
(`addons/godot_mcp_toolkit/core/plugin_composer.gd:65-69`, `compose`):

```gdscript
var session_tracker := DebugSessionTracker.new(EditorInterface)
var debug_bridge := DebugBridge.new(session_tracker)
plugin.add_debugger_plugin(debug_bridge)

BuiltinCommandRegistration.register_all(registry, server, debug_bridge, session_tracker)
```

The playtest registrar receives the tracker as a `register(...)` parameter, and the composer's
teardown undoes the registration through `PlaytestCommands.clear_session_tracker()`
(`addons/godot_mcp_toolkit/commands/playtest/playtest_commands.gd:18-20` at commit `111bdd5`;
teardown at `core/plugin_composer.gd:336` on `main`). The reader keeps it in a `static var`, one of the
holders B2 lists under 7.13:

```gdscript
static func register(registry: MCPToolkitCommandRegistry, _server: Node,
		session_tracker: DebugSessionTracker) -> void:
	_LogReader.set_session_tracker(session_tracker)
```

## Bad

A user that defaults its own copy. The log reader starts with a tracker it builds itself, and
builds a fresh one again when the root clears the injected one
(`addons/godot_mcp_toolkit/commands/playtest_log_reader.gd:37`, `:66`):

```gdscript
static var _session_tracker: DebugSessionTracker = DebugSessionTracker.new()
```

```gdscript
static func clear_session_tracker() -> void:
	_session_tracker = DebugSessionTracker.new()
	_session_tracker_injected = false
```

The stand-in is deliberate (`game.start` can mark a playtest before any tracker is injected), so
it is one of the existing cases B2 lists rather than a pattern to copy. A new collaborator takes
the injected instance and, with none, reports that it has none.
